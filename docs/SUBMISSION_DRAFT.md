## Eight-slide content

### 1. Problem and user

Small-wholesaler operations coordinators need to understand why an order may miss its promised date. Order, stock and supplier statements can disagree or become stale. Order Evidence asks one focused question and keeps the records behind each answer inspectable. Market impact has not been measured.

### 2. Solution

One synthetic order workspace shows status, supported causes, uncertainty, evidence timeline and a draft for human review. Each source has immutable identity/version and observation/effective times. Changed evidence creates a linked revision and invalidates the earlier approval. No messages, purchases or real order changes occur.

### 3. Agent workflow

The genuine pinned Meterless Markovian executor drives retrieval, then assessment. A deterministic policy checks dates, quantities, scope and freshness. In Live mode, Nightshift is asked for a bounded evidence-supported selection, checked with at most one correction. Failed validation yields uncertainty. Live inference has not yet been executed.

### 4. Stack

Node24.19, built-in HTTP/fetch/test/fs/crypto, ES modules and the experimental TypeScript transform flag for unchanged imported Meterless source. Semantic HTML/CSS/JavaScript workspace, local Geist fonts, zero runtime npm dependencies. Atomic file persistence owns investigation/revision identity and approval history. Pre-existing imported components disclosed.

### 5. Zetaris role

The intended live data boundary is a bounded query of a governed synthetic evidence view through the existing local Zetaris account proxy. Credentials stay server-side. A generic vendor platform check passed9/9 October19; current images are restoring. Application source registration and response mapping remain unverified. No application-level Zetaris execution is claimed by this draft.

### 6. Meterless and unique use

Actual Markovian callbacks drive retrieval and assessment, rather than logging a completed app-owned answer.20/20 preview evaluation runs completed through the unchanged Apache2 reference. Business revisions and approval invalidation are persisted separately. Nightshift primary-provider adapter is implemented but blocked from live verification. No NVIDIA model or award eligibility is claimed.

### 7. Actual product and evidence

Use `preview-oct22.png`, captured from the running app. Show order003 at risk, cite supplier version1, approve the draft in the synthetic demonstration, apply U01 and inspect revision2 on track. The old approval is historical/invalidated. Automated checks:24/24 pass;20/20 exact preview classifications;5/5 uncertainty cases;10/10 update checks; two process restarts preserve state. Provider HTTP tests use explicit fakes and are not live sponsor proof.

### 8. Limitations and next improvements

First release is synthetic, single-order and local. Live source/model gates, actual billing/latency, Cursor development evidence remain incomplete. After those gates close, prioritize measured semantic citation audit, realistic source onboarding and operational user feedback. No production, customer adoption or financial impact claim.
